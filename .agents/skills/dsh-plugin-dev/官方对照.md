# 官方对照 — 与官方文档的出入与采用结论

> 本 skill 的原则：**以官方文档为准**；现有做法（dsh-message-injector 的开发经验）与官方有出入的，逐条列在这里，skill 采用官方正确的方式；无法采用的（官方未发布/未验证），如实说明原因与切换条件。

## 2026-10-09 更新（harness 0.2.0-rc.2）— settings 架构重构

以下结论已按 0.2.0-rc.2 实机安装包逐项核对（核对方法：直接读 `node_modules/@deepseek-ai/dsh/...` 的包源码与类型 + 已适配第三方插件源码）：

| 主题 | 0.1.x 做法 | 0.2.0 现状 | 采用 |
|---|---|---|---|
| 宿主配置注册 | `installSettingsSection` + `settingsNamespace`（@deepseek-ai/dsh-settings） | **导出删除**；改为「导出 `Config` schema + 字段 `.volatile()`」，命名空间 = Loader 条目 id | 新模型（§3.3） |
| 配置读取 | `scope.get()`（SettingsScope） | `apply(ctx, config)` 的 `config.<字段>.get()`（Volatile 引用） | 新模型 |
| 配置变更 | `scope.watch(cb)` | `ctx.on('loader/volatile-update', cb)`（按 fiber 过滤） | 新模型 |
| 配置写入（后端） | `scope.update(patch)` | `ctx.get('settings')?.update(条目id, patch)` | 新模型 |
| 保存校验 | `validate` 钩子（throw 拒绝写入） | **无对应钩子**（仅 schema 结构校验）；跨字段校验放前端保存前 + 后端容错 | 前端拦截 + 容错消费 |
| 自绘配置页 | 无此概念 | `settings.configure({ auto: false }, ctx.fiber)`（写在 `ctx.inject(['settings'], ...)` 里） | 官方姿势 |
| 前端读写 | `ctx.settingsScope.bind({namespace})` | `ctx.configForms.get(条目id)`（ConfigForm：稳定快照/subscribe/set/mutate；set 返回 boolean） | 官方姿势 |
| 配置卡槽位 | `settings.plugin.item`（设置→插件→插件配置） | **槽位删除**；官方配置卡在 Plugins 页：`plugins.bundle.config`（key=包名）/ `plugins.row.config`（key=包名#行id）/ `plugins.item` | `plugins.bundle.config` + `whileServed` 门控 |
| 页面导航 | 无公共 API（DOM aria 折中，见旧版坑 8） | `ctx.pluginNavigation.openBundle(包名)`（官方公开服务） | 官方服务 + 逐级降级 |
| 技能目录 | `ctx.connection.api.skills.list` | `ctx.remote.skills.list({sessionId}, signal)`（RemoteResult） | 官方姿势 |
| 当前会话 | `sessions.list.getSnapshot().current` | 该字段删除；按 `retainedBy.mainView > 0` 找 | 官方统一写法 |
| 持久化位置 | `$DSH_HOME/settings.yaml` 命名空间抽屉 | profile 补丁 `$DSH_HOME/profiles/<p>/cordis.patch.yml` 条目段落；旧文件改名 `settings.yaml.imported`（官方只迁移内建段落） | 新模型 + 插件自建一次性导入 |
| `dsh.client.inject` | 误写服务名 | 官方类型定义明确是**包名清单**（informational，模块到达顺序） | 包名清单 |
| 版本门禁 | 无 | `peerDependencies`（`@deepseek-ai/dsh` / `@deepseek-ai/dsh-*`）被启动门禁检查，不满足则跳过 bundle 并提示 | 声明 peer 指明兼容范围 |

## 出入清单

| # | 主题 | 官方做法 | 本项目/经验文档做法 | skill 采用 |
|---|---|---|---|---|
| 1 | patch 文件名 | 示例 `cordis.patch.yml` | `bundle.patch.yml`（文件名任意，由 `dsh.bundle.patch` 引用） | 模板用官方名 `cordis.patch.yml`；本项目历史文件名不动（能用），差异记于此 |
| 2 | `files` 白名单 | manifest 含 `files` 字段 | 缺失（npm 发布会漏产物） | 模板补 `files: ["lib", "cordis.patch.yml"]` |
| 3 | `--patch` 开发 overlay | 官方教程主流程（绝对路径） | 因隐私问题放弃（坑 4） | 以官方安装路径为主；`--patch` 仅注明存在，不采用 |
| 4 | GitHub 安装 | 拉源码不构建 → 作者配 `prepare` 脚本 + 用户 `allowBuilds` 授权 + 建议锁 commit sha；或发布 npm / 交付 `pnpm pack` tarball | 只说"克隆副本、更新重新 add"（不完整） | 采用官方完整做法（含安全警告：授权 = 允许代码在机器上执行） |
| 5 | 安装验证 | `dsh --profile <name> --dump-config` 离线看层 | 只看 profile bundles 列表 | 两者都给（SKILL.md 步骤 3） |
| 6 | 层加载顺序 | bundles 按序 → profile 的 cordis.patch.yml → `$DSH_HOME/cordis.patch.yml` → `--patch` overlays；后层按行胜出，patch **整行替换** config 非深合并 | 未提及 | SKILL.md 注明；覆盖用户配置默认值应给"用户大概率保留"的值 |
| 7 | 业务组件订阅 | 官方家规：业务组件**零手写订阅**（用 `createSnapshotStore` + inject face 的 `hooks` 口子，渲染器绑成 `use<Name>()` 钩子） | `useSyncExternalStore` 直读 settingsScope（坑 7 箭头函数补丁） | **基线版本错位**：`@deepseek-ai/dsh-client-store` 仅 master 基线，npm 最新 0.1.1-rc.2 无此种子（运行时实测 missed the module table）。故 skill 步骤 1 先确认版本与支持面：基线就绪 → 官方 store+hooks 写法；未就绪 → 用本项目验证过的 uSES 写法，待基线发布后切换（切换点：`createSnapshotStore` + `hooks: {name: store}` + `use<Name>(selector)`，参考官方 dsh-client-ui-settings-plugins） |
| 8 | 术语 | host half / client half、组合包（bundle）、profile | 统一"后端/前端" | 官方术语为主（SKILL.md/REFERENCE.md），"前端/后端"仅在对照时提及；组合包/profile 用官方词 |
| 9 | 客户端依赖声明 | `dsh.client.inject`（服务列表）+ `dsh.client.external`（模块图请求，仅基础设施用） | 只用 `dsh.client.inject`（正确，无需 external） | 一致，采用；`external` 只在需要非基线模块时声明 |

## 一致项（本项目 = 官方，直接采用）

- 插件三形态、`apply(ctx)`、`inject` 依赖、`ctx.effect` 自动清理
- 前端必须预构建（`lib/client.js`，`__ModuleLoader__.load` 形态；浏览器无 TS 编译；JSX 必须 `.tsx`）
- `dsh plugin --profile <name> add|remove` 官方安装路径（本地 = 软链接）
- `dsh.bundle.patch` 机制、`exports["./client"]`、`dsh.client.platform: "web"`
- 槽位名 `conversation.input.left`、`settings.plugin.item`（官方运行时存在）
- `installSettingsSection`/`settingsNamespace`（dsh-settings 官方导出）
- 技能会话级激活、重复注入无去重（官方工具行为，本项目实测）

## 采用结论

1. 凡官方已发布且验证过的 → skill 全用官方方式（#1/#2/#4/#5/#6/#9）。
2. 官方教程存在但本项目有意不用的（#3 `--patch`）→ 不采用，理由记录在案。
3. 官方 master 有、发布版没有的（#7 store 基线）→ **先确认版本，未就绪用验证过的等价写法**，切换条件写清。
