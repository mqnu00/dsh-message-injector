# 迭代记录

> 按时间线记录迭代过程与决策背景。**CHANGELOG.md 是结果清单，本文档是过程记录**——为什么这么做、踩了什么坑、怎么拍板的。

## 2026-08-30 — 从零到开源（一次完整迭代）

### 阶段 1：需求讨论与定位（/grill-with-docs 逐项确认）

- 最初设想「技能预设自动填充」（`dsh-skill-injector`）：预设常用技能组合，自动填入输入框。
- **一个事实推翻定位**：dsh 技能是**会话级激活**的——一个会话只需注入一次，手动输入即可；而"每条消息注入固定内容"才是真实需求。更名 `dsh-message-injector`，内容泛化为任意文本（`/` 开头行视为技能调用，保留存在性校验）。
- 术语表（CONTEXT.md）、需求文档（需求.md）在此阶段成型。

### 阶段 2：骨架与最小回路

- 双半区结构 + 三声明（`dsh.bundle` / `exports["./client"]` / 入口）齐活。
- 踩坑实录（详见 开发经验.md）：
  - 缺 `dsh.bundle` → 装了不生效；
  - `useSyncExternalStore` 裸方法丢 `this` → 渲染崩溃；
  - `ctx.logger` 是服务工厂 → `.info` 静默无效。

### 阶段 3：文档体系

- README 精简为门面页，细节拆分 `docs/zh` + `docs/en`；术语统一"前端/后端"；位置描述改为用户可感知的"输入框左下角"。

### 阶段 4：配置卡 UI 对齐官方

- 手写样式配置卡与官方卡（WebSearch/Bash/AgentLoop）格格不入 → 照抄官方视觉参数（radius 12 / border l2 / bg layer-3 / input 34px），全走 `--dsw-alias-*` 令牌 + 自有类名（**禁止引用 dsh 内部哈希类名**）。
- 抽象通用组件 `ConfigCard`（折叠标题栏 + 表单体 + 放弃/保存脚注 + 展开信号）。
- 交互打磨：组折叠（默认收起）、新增组压栈首位、添加后自动滚动露出。

### 阶段 5：设置直达

- 需求：选择器菜单底部「设置」→ 一键打开设置面板并展开配置卡。
- 事实：dsh 无公共 API（SettingsRoot 的 open/分区均为内部 state）→ 采用官方 aria 属性（`button[aria-haspopup="dialog"]`）+ 官方导航文案（`插件`/`Plugins`）定位，配置卡展开用**一次性信号**（挂起/消费/订阅），任一步失败优雅降级。

### 阶段 6：结构重构

- `src/` 按官方 half 分法分 `host/`（后端）/ `client/`（前端），领域类型抽 `shared/types.ts`。
- 前端按职责分层：`types/`（契约类型）`api/`（数据访问）`services/`（业务服务）`logic/`（纯逻辑）`locales/`（词典）`utils/`（通用工具）`components/`（UI 组件），入口 `index.tsx` 只做接线。
- 滚动控制/一次性信号/CSS 注入/设置定位/技能目录抽象为通用模块。
- 自带 skill（`.agents/dsh-plugin-dev`）与模板同构重构。

### 阶段 7：开源准备

- **安全审计**：全部提交历史 + 不可达对象扫描（密钥/绝对路径/邮箱/IP 零命中），真实身份匿名化（noreply 邮箱）、31 个不可达对象物理清除（`reflog expire` + `gc --prune=now`）。
- 新增 LICENSE（MIT）、npm `keywords`（dsh-plugin 等，GitHub topic 需推送后在仓库页设置）。
- README 说明配置存储位置（`$DSH_HOME/settings.yaml`）；使用说明补「使用建议」（长文本整理为 SKILL）与「典型使用流程」。

## 2026-10-09 — 适配 dsh 0.2.0（settings 架构重构）

### 背景

- dsh 升级到 `0.2.0-rc.2`（npm latest）。0.1.0 版插件在新版上是**整页级故障**：宿主半 `sctx.settings.register is not a function`、前端半 `pending (waiting for service: settingsScope)` → web 停在 `Failed to load plugins`（升级演练报告：隔离安装 0.2.0-rc.2 + headless 浏览器实测，结论 = 插件必须适配后才能在 0.2 上加载）。

### 阶段 1：新旧 API 对照（以实机安装包 + 已适配插件为准）

- 派子代理逐包核对 0.2.0 安装包（`~/.nvm/.../@deepseek-ai/dsh/node_modules`），确认：`installSettingsSection`/`settingsNamespace`/`settingsScope`/`settings.plugin.item` 全删；新模型 = Loader 条目 id 命名空间 + `.volatile()` 字段 + `loader/volatile-update` + `configForms`（客户端）+ `plugins.bundle.config`（Plugins 页槽）+ `pluginNavigation.openBundle`（导航）。
- 参照两位"同学"：**dsh-better-sidebar 0.24.1**（ownEntryId 反查、legacy 导入、settings.update 写法）与 **dsh-llm-retry-settings 0.1.16**（0.1/0.2 特性探测分支、volatile-update 用法）。

### 阶段 2：宿主半迁移

- `Config` 改 `.volatile()`；`apply(ctx, config)` 经 `config.groups.get()/config.selected.get()` 读实时值。
- 自动反选（F6-6）：初版按事件模型改挂 `ctx.on('loader/volatile-update')` 回写 `selected`，代码审查发现**该事件在 HMR 事务内触发，嵌套写必被拒**（"HMR transactions cannot be nested"，实测判据见 开发经验.md 坑 13）→ 最终改为前端保存时与 `groups` 同一次 mutate 原子清理 + 消费侧守卫。
- 自绘配置卡 → `settings.configure({ auto: false }, ctx.fiber)`。
- **旧数据一次性导入**：读 `$DSH_HOME/settings.yaml(.imported)` 的 `message-injector` 段落，仅在 user 层为空时写入新条目（参考 better-sidebar 的 importLegacyPrefs；本机实测旧数据确实留在 `.imported` 里）。
- 硬校验迁移决策：0.2.0 无 per-namespace `validate`——组名唯一/内容非空由前端配置卡保存前拦截，后端消费侧容错（失效选中由守卫兜底）。

### 阶段 3：前端半迁移

- `settingsScope.bind({namespace})` → `ctx.configForms.get('dsh-message-injector')`，入口适配为 `ScopeLike`（组件零改动接口；`set` 返回 boolean，不再假设成功）。
- 配置卡槽 `settings.plugin.item` → `plugins.bundle.config`（key = 包名），`whileServed` 门控；`ConfigCard` 根元素 li → div（新容器不是列表）。
- 「设置直达」：`pluginNavigation.openBundle(包名)` 为主，`layout.selectPanel('plugins')` + DOM 兜底为辅；展开信号机制不变。
- 技能目录 `connection.api.skills` → `ctx.remote.skills.list`（RemoteResult）；当前会话定位 → `retainedBy.mainView`（新增 `utils/session.ts`）。
- 新增只读/未接受提示（memory 模式与 revision 拒绝）。

### 阶段 4：工程与验证

- `package.json`：版本 0.2.0；加 peer/engines 版本门禁；`dsh.client.inject` 改包名清单；删 `dsh-settings`、schemastery `^3.18.4`、加 `yaml`。
- 新增 `pnpm-workspace.yaml`（`autoInstallPeers: false`——否则 pnpm 会把整个 dsh 拉成依赖，实测超时）。
- 迁移四坑（详见 开发经验.md 坑 9-12）：环境模块声明遮蔽真模块、cordis 4 effect 必须返回 disposer、peer 自动安装、旧 helper 必须整体移除。
- 验证：`pnpm typecheck` + `pnpm build` 通过；**安装与浏览器实测按项目纪律由用户执行**（高压线：不自启动 dsh、不碰 dsh 配置）。
