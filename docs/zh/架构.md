# 架构

## 前端 + 后端

> dsh 官方把这两部分叫 **host half / client half**（宿主半区/客户端半区），本质就是**后端 / 前端**：后端跑在 dsh 服务端进程里（配置、校验、持久化），前端跑在浏览器里（按钮、表单、自动注入）。本文档统一用"后端/前端"。

## 目录结构

```
dsh-message-injector/
├── package.json            # 插件身份证：dsh.bundle（激活）+ dsh.client（前端声明）+ exports["./client"] + peerDependencies（dsh 0.2.x 版本门禁）
├── bundle.patch.yml         # 激活补丁：insert 条目 id = dsh-message-injector（= 包名 = 0.2.0 settings 命名空间）
├── pnpm-workspace.yaml      # pnpm 配置：autoInstallPeers=false（peer 由 dsh 运行时提供）+ allowBuilds（esbuild）
├── src/                             # 按官方 half 分法：host（后端）/ client（前端）
│   ├── host/
│   │   ├── index.ts            # 后端源码：Config schema（.volatile()）+ 自绘配置页声明 + 旧数据导入
│   │   └── node-stubs.d.ts     # 类型桩：node:fs/promises、node:path（环境模块声明）
│   ├── shared/
│   │   └── types.ts            # 领域类型 PresetGroup/PresetConfig（两端共用，纯类型）
│   └── client/                 # 前端源码（全部浏览器代码；构建为 lib/client.js）
│       ├── index.tsx           # 前端入口（组合根：只做接线）
│       ├── types/              # 契约类型（ScopeLike/ConfigFormLike/InputLike/RootCtx 等防御式服务类型）
│       ├── api/                # 数据访问（skills.ts：技能目录接口 + 30s TTL 缓存）
│       ├── services/           # 业务服务（injector.ts：自动注入轮询，F4/F5）
│       ├── logic/              # 纯业务逻辑（normalizeContent/isSkillLine/skillNameOf/cloneGroup）
│       ├── locales/            # 词典（zh/en）
│       ├── utils/              # 通用工具（scroll/css/signal/session/navigation）
│       ├── components/         # UI 组件（ConfigCard/PresetSelector/PresetConfigCard）
│       └── ambient.d.ts        # 最小类型桩（react / primitives 由浏览器运行时提供）
├── scripts/build.mjs       # esbuild 构建（pnpm build）：后端 → lib/index.js，前端 → lib/client.js
├── lib/index.js            # 后端构建产物（已提交）
├── lib/client.js           # 前端构建产物（已提交；改前端代码后需重新 pnpm build）
└── docs/
    ├── zh/                 # 中文文档（安装 / 使用说明 / 架构 / 需求 / 迭代记录）
    └── en/                 # 英文文档（Install / Usage / Architecture）
```

> 仓库**不包含** `cordis.yml` / `--patch` 本地加载配置。插件统一走官方 `dsh plugin add/remove` 安装。

## 构建

```bash
pnpm install          # 安装依赖（schemastery / yaml / esbuild / typescript）
pnpm build            # 构建 → lib/index.js + lib/client.js
pnpm typecheck        # tsc --noEmit 类型检查
```

> 本插件是**第一个外部调用 `setDraft` 输入写入通道的插件**（dsh 源码中无先例），该通道虽为官方公开 API，但测试时建议重点验证注入行为。

## dsh 0.2.0 适配（settings 架构重构）

dsh 0.2.0 移除了旧的 settings provider 体系（`installSettingsSection` / `settingsNamespace` / `settingsScope` 全部删除），改为「Loader 条目配置的 volatile 字段表单投影」：

- **命名空间**：不再是插件自定义字符串，而是 **Loader 条目 id**（本插件 = `bundle.patch.yml` 的 id = 包名 `dsh-message-injector`）
- **配置声明**：后端导出 `Config` schema，参与配置卡/持久化的字段必须 `.volatile()`；`apply(ctx, config)` 里经 `config.groups.get() / config.selected.get()` 读实时值
- **持久化位置**：写入落在 profile 补丁 `$DSH_HOME/profiles/<profile>/cordis.patch.yml` 的 `dsh-message-injector` 条目（由官方 settings 服务与 config-editor 完成），不再是 `$DSH_HOME/settings.yaml`
- **变更通知**：`ctx.on('loader/volatile-update', cb)` 可用（事件按 fiber 过滤，只发本条目），但**不能在回调里回写配置**——该事件在 HMR 事务内同步触发，嵌套 `runExclusive` 必被拒（"HMR transactions cannot be nested"）
- **前端读写**：`ctx.configForms.get(条目id)`（ConfigForm：稳定快照 + subscribe + set/mutate；`set` resolve `false` = 被拒绝/只读，传输错误才 reject）→ 入口适配为 `ScopeLike`，组件不直接依赖官方类型
- **配置卡挂载点**：旧 `settings.plugin.item` 槽已删除。0.2.0 官方配置卡位于 Plugins 页（`plugins.bundle.config` / `plugins.row.config` / `plugins.item`）；本插件注册 `plugins.bundle.config`（key = 包名），并用 `configForms.whileServed([id], ...)` 门控（宿主未服务该命名空间时不出现空卡）
- **硬校验迁移**：0.2.0 无 per-namespace `validate` 钩子（写入仅经 schema 结构校验）——组名唯一/内容非空由前端配置卡保存前拦截（实时字段级错误 + 保存禁用），后端消费侧保持容错
- **自动反选（F6-6）迁移**：因为 volatile-update 回调内不能回写（见上），改在前端配置卡保存时与 `groups` **同一次 mutate 原子清理** `selected`（删除/禁用选中组的唯一入口就是配置卡保存）；选择器与注入轮询另有消费侧守卫（selected 指向不存在/禁用的组 → 视为未选中、不注入），外部改配置等边缘场景优雅降级
- **旧数据导入**：启动后一次性读取 `$DSH_HOME/settings.yaml(.imported)` 的 `message-injector` 段落写入新条目（仅在条目 user 层为空时执行，绝不覆盖升级后的修改；参考 dsh-better-sidebar 的 importLegacyPrefs）

## 关键机制（开发时已核实）

- **UI 注入**：`ctx.slots.inject('conversation.input.left', ...)` 注册列表槽组件（输入框左下角的官方座位）；配置卡走 `plugins.bundle.config`（key = 包名 `dsh-message-injector`）
- **配置卡形态**：复刻 dsh 官方配置卡壳（可折叠标题栏 + 表单体 + 放弃/保存脚注），已抽象为**通用组件 `src/client/components/ConfigCard.tsx`**——props：title/description/children/dirty/saving/invalid/failed/onSave/onDiscard + 展开信号 `expandSignal`（挂起/订阅）+ 信号展开后自动滚动露出；字段样式类（psi-field/input/textarea/check 等）随组件 CSS 一并注入，供 children 使用；视觉参数照抄官方（radius 12 / border l2 / bg layer-3 / input 34px），全部走 `--dsw-alias-*` 令牌 + 自有类名；**禁止引用 dsh 内部 CSS 类名**（构建哈希，升级即断，见开发经验「坑 7」）
- **设置快捷入口**：选择器菜单底部「设置」→ 模块级展开信号（卡已挂载立即展开；未挂载挂起、挂载即展开）+ 官方导航服务 `ctx.get('pluginNavigation')?.openBundle(包名)`（切 Plugins 面板 + 打开包详情页；缺失时降级 `layout.selectPanel('plugins')`，最后 DOM 兜底 `li[data-plugin-package]`）；任一步失败优雅降级（见开发经验「dsh 0.2.0 迁移坑」）
- **滚动控制**：通用模块 `src/client/utils/scroll.ts`——`scrollElementIntoView`（对齐到最近可滚动容器，start/center/nearest 三档）+ `useReveal(open, when)` 钩子（信号触发一次性滚动，手动操作不打扰）；新增组露出、设置直达后露出配置卡均复用它
- **CSS 注入**：通用工具 `src/client/utils/css.ts` 的 `injectStyle(tagId, css)`（data-plugin-css 机制，同 tagId 只注入一次）；配置卡样式由 ConfigCard 组件注入，选择器/组块样式由各自组件注入
- **前端分层**：入口 `index.tsx` 只做接线（组合根）；组件（components/）、数据访问（api/）、业务服务（services/）、纯逻辑（logic/）、词典（locales/）、通用工具（utils/）按职责归目录；设置直达的信号用 `utils/signal.ts` 的一次性信号，插件页导航用 `utils/navigation.ts`，当前会话定位用 `utils/session.ts`
- **输入读写**：官方通道 `input.setDraft(text)`（`conversation.input.for(actx)`，React 受控组件，禁止直接改 DOM）；判空读 `input.state.getSnapshot()`（draft/phase）
- **配置持久化**：后端导出 `.volatile()` Config（命名空间 = 条目 id）；前端 `ctx.configForms.get(条目id)` 读写（跨标签页同步）
- **当前会话定位**：dsh 0.2.0 的 `SessionListState` 无 `current` 字段——按 `retainedBy.mainView > 0` 找当前打开的会话（官方统一写法，见 `utils/session.ts`）
- **技能校验**：`ctx.remote.skills.list({sessionId})` 校验 `/` 开头的技能调用行（旧 `connection.api.skills` 已移除；无会话时校验不可用 → 技能调用行按配置原样注入）

## 踩坑记录

- `useSyncExternalStore` 必须用箭头函数包裹 `scope.getSnapshot/subscribe`，否则丢失 `this` 导致渲染崩溃（ConfigForm 的方法依赖 `this.store`）
- 前端必须**预构建**为纯 JS（浏览器无 TS 编译），产物走 `window.__ModuleLoader__.load({id, factory})` 形态
- 插件必须在 package.json 声明 `dsh.bundle`，`dsh plugin add` 才会把它挂载为 profile 层（否则只是普通依赖，不生效）
- dsh 内部 CSS 类名是构建哈希（如 `YyYd_a_card`），引用即升级即断——只信 `--dsw-alias-*` 设计令牌（坑 7）
- dsh 0.2.0 迁移六坑（详见 `docs/zh/开发经验.md` 坑 9-13 与审查发现）：① 旧 settings helper 必须整体移除，不能「保留兼容分支」（0.2.0 上模块链接期就会坏）；② `declare module` 真模块写在非模块 .d.ts 里会**遮蔽**该模块全部导出，模块增强必须写在有 import/export 的文件里；③ cordis 4 的 `ctx.effect` 回调必须返回 disposer（不能返回 undefined）；④ `pnpm install` 需 `autoInstallPeers: false`（否则把整个 dsh 拉下来）；⑤ **不能在任何 HMR 写事务内回写配置**（`loader/volatile-update` 回调里 `settings.update` 必被拒）——反选清理放到保存方同一次 `mutate`；⑥ 前端 primitives 的 **图标名换代**（0.2.0 为 `Icon*OutlineRegular/Medium`，`Icon*Outline14/16` 全部不存在，渲染即崩）——升级时先对照真包导出清单
